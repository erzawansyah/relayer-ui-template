# relayer-ui-template

A contract-agnostic React UI for interacting with FHEVM (Zama) smart contracts. It reads a list of contracts plus their ABI and metadata from `public/contracts/`, renders their documentation, and lets you call read/write functions with encrypted inputs and decrypted outputs.

This repo is the frontend template used by [fhevm-starterkit](https://github.com/erzawansyah/fhevm-starterkit). The starterkit clones it (at a pinned commit) into every generated project as the `ui/` folder and fills `public/contracts/` for you. On its own, without contracts, the UI shows an empty selector.

## Status and compatibility

| Component | Version |
|---|---|
| FHEVM (`@fhevm/solidity`) | 0.9.x |
| Relayer SDK (loaded from Zama CDN) | `0.3.0-5` |
| Mock utilities (`@fhevm/mock-utils`) | 0.1.x |

**Sepolia is no longer supported.** Relayer SDK 0.3.0-5 talks to the old Zama testnet relayer (`relayer.testnet.zama.org`), which no longer serves requests, so creating an FHEVM instance on Sepolia fails. This template is not being upgraded to newer FHEVM releases. Use **local mode**: a Hardhat node on chain `31337`, where encryption and decryption run through `@fhevm/mock-utils` and no relayer is needed.

## Features

- Contract selector driven by `public/contracts/index.json`
- Documentation tab rendered from each contract's metadata
- Read and write function execution, with encrypted inputs (`euint*`, `ebool`, `eaddress`) and user decryption of results
- Wallet connection via RainbowKit / wagmi (Hardhat local chain, Sepolia kept for reference only)
- Light/dark theme

## Quick start (local mode)

Requirements: Node.js 20+, a running Hardhat node with FHEVM mock support (for example a project generated by `fhevm-starterkit`).

```bash
npm ci
cp .env.example .env.local    # fill VITE_WALLETCONNECT_PROJECT_ID (any non-empty value works for local use)
npm run dev
```

Then, in your browser wallet, add the Hardhat network (`http://127.0.0.1:8545`, chain ID `31337`) and import one of the Hardhat test accounts.

The easiest path is to let the starterkit do everything:

```bash
git clone https://github.com/erzawansyah/fhevm-starterkit
cd fhevm-starterkit && npm install
npm run template:init
npm run starter:create fhe-counter -- --dir my-project
```

## Contract files

The UI loads everything from `public/contracts/` at runtime:

```
public/contracts/
  index.json                 # ["fhe-counter", "..."]  list of contract slugs
  fhe-counter/
    abi.json                 # { "abi": [...] }
    metadata.json            # see src/types/metadata.d.ts
```

`metadata.json` follows `ContractMetadataType` in `src/types/metadata.d.ts`. The important field for the UI is `contract_address`, a map from chain ID to deployed address:

```json
{
  "name": "fhe-counter",
  "label": "FHE Counter",
  "contract_name": "FHECounter",
  "contract_address": { "31337": "0x..." },
  "fhevm_version": "0.9.1"
}
```

These files are generated by `fhevm-starterkit` and are git-ignored here.

## Project structure

```
src/
  components/        UI components (components/ui = shadcn primitives)
  context/, hooks/   contract loading, encryption, decryption, input preparation
  lib/fhevm/         FHEVM React integration derived from Zama (BSD-3-Clause-Clear)
  types/             contract metadata and function types
  wagmi.config.ts    chains and wallet config
public/contracts/    contract ABI + metadata (filled by fhevm-starterkit)
```

## Stack

Vite 7, React 19 (React Compiler), TypeScript 5.9, Tailwind CSS 4, shadcn/ui, wagmi 2, viem, RainbowKit, ethers 6, TanStack Query.
